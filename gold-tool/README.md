# gold-tool

Labeling UI for the Phase 2 gold test set: 300 comments, stratified from
`data/samples/silver_20000_seed7.jsonl`, double-coded and then adjudicated
against each other and against the LLM consensus.

> **Provenance warning.** The 300-comment pass in `server/data/gold_labels.sqlite`
> was *not* hand-annotated. The `A` rows are `claude-sonnet-5`'s output and
> the `B` rows are `gemini-3.5-flash`'s, bulk-loaded under the annotator
> names (every row carries the same `updated_at`). So the κ≈0.80 / span-F1≈57%
> in `data/labels/gold/iaa_report.md` is **model–model agreement, not human IAA**,
> and `adjudicated.jsonl` is an LLM-adjudicated gold set — its disagreements were
> resolved by those same two models debating each other in `pipeline/debate.py`.
> See "Human gold pass" below for the real hand-annotated set.

Sample: `data/samples/gold_300_seed7.jsonl`, drawn via
`python -m pipeline.sample --gold --n 300 --seed 7` (mirrors the 20k's
random/topic/emotive proportions; topic slice spread evenly across all 14
cause-taxonomy categories).

## Run it

```bash
# terminal 1 — API + SQLite storage (data/gold_labels.sqlite)
cd server
npm install   # first time only
node index.js

# terminal 2 — UI
cd client
npm install   # first time only
npm run dev
```

Open the client URL (defaults to http://localhost:5173) and pick your name.
Labels save per (comment, annotator) — both annotators label all 300
independently; the tool doesn't show you the other person's answers.

The "model said" panel reads live from
`data/labels/silver/deepseek_deepseek-v4-flash.raw.jsonl` as the silver
annotation run progresses, so predictions fill in over time — a comment may
show "pending" if the run hasn't reached it yet.

## Adjudication

Once both annotators have double-coded all 300, switch to the
**Adjudication** tab (top of the header) to resolve the disagreements. It
lists exactly the comments where A and B's independent calls
don't match (same criterion as `pipeline/gold_report.py`'s IAA computation:
neutral/emotive mismatch, an unmatched pair, or a differing emotion/
cause_category on a matched pair — 173/300 as of the last IAA run).

For each one you get: the comment in context, both annotators' pairs side by
side ("use this pair" copies one into the custom editor), a small discussion
thread to hash out *why* before committing, and a final-call picker —
A's version, B's version, Neutral, or a hand-edited Custom set of
pairs (same verbatim-span rules as regular labeling). Once all 173 are
resolved, **Export gold standard** writes `data/labels/gold/adjudicated.jsonl`
(merging in the 127 comments that already agreed) — the same file
`python -m pipeline.gold_report --apply-worklist ...` used to produce, so
`pipeline/gold_report.py --score-silver` keeps working unchanged. The
markdown worklist (`adjudication_worklist.md`) is still generated by
`pipeline/gold_report.py` for reference/offline reading, but this page is now
the actual mechanism for finishing the adjudication pass.

## Human gold pass (100 comments, single annotator)

The one set with a human in it — what makes the LLM numbers checkable.

```bash
./run_human_gold.sh            # blind: model panels hidden
./run_human_gold.sh --assist   # curated: pooled candidates, click-to-accept
```

> **The released benchmark used `--assist`.** It is hand-*curated*, not blind:
> the annotator worked from pooled machine candidates, keeping the correct ones,
> discarding the rest, rewriting fields where a span was right but its labels
> were not, and marking neutral where nothing held. Every kept pair in
> `data/labels/gold/human_gold_100.offsets.jsonl` carries `_accepted_from`
> naming its source, so this is verifiable from the file. The consequence:
> agreement measures how readily a human *endorses* a model pair, and the
> shared-bias rate is a **floor** (only outright rejections count), not an
> estimate. The blind mode below is what would tighten it.

- **Sample**: `data/samples/human_gold_100_seed7.jsonl` — 100 comments drawn with
  the same stratifier as everything else in the paper
  (`python -m pipeline.sample --gold --n 100 --seed 7 --src data/samples/gold_300_seed7.jsonl`),
  so 15 random / 42 topic / 43 emotive with the topic slice spread 3-per-bucket
  across all 14 cause categories. Every one is a **subset of the 300**, so each
  human label has a `claude-sonnet-5` and a `gemini-3.5-flash` label to compare
  against.
- **Blind mode** (`GOLD_BLIND=1`, the default without `--assist`): the server
  withholds model + consensus predictions entirely, so agreement cannot be
  anchoring. Not what the released set used — see the note above.
- **Separate store**: writes `data/labels/gold/human_gold_labels.sqlite`, so the
  300-comment store is untouched and the two can never be confused.
- **Single annotator**: `GOLD_ANNOTATORS=A-human`; the adjudication tab is
  off (it's a two-coder concept).

Score it any time — partial progress is fine:

```bash
python -m pipeline.human_gold_eval              # -> data/labels/gold/human_gold_report.md
python -m pipeline.human_gold_eval --export     # also dump labels to JSONL
python -m pipeline.human_gold_eval --self-test  # verify the harness with no annotation done
```

The report gives human-vs-model agreement in the same metrics as the existing
IAA table, the **shared-model-bias decomposition** (of the decisions where both
models agreed, how many did the human score differently — the error class
LLM-only IAA cannot see), and sarcasm-flag precision/recall against the human.

Server env vars, if you want a different configuration: `GOLD_SAMPLE` (item set),
`GOLD_DB` (sqlite path), `GOLD_ANNOTATORS` (comma-separated roster), `GOLD_BLIND`.

## Notes

- Spans are captured by highlighting text in the rendered post title / parent
  comment / comment, then clicking "Capture selection" in the pair editor —
  this guarantees verbatim spans by construction. The server independently
  re-validates verbatim-ness and derives `cause_source` (comment > parent >
  post precedence, per spec §4) — it never trusts a client-supplied source.
- The server has no authentication and binds localhost by default: it assumes a
  single trusted machine. Put it behind your own tunnel or reverse proxy if a
  second annotator needs to reach it.
